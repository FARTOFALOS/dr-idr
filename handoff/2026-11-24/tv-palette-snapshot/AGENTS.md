# tv-palette — dark palette for TradingView with rollback

Read `manifest.json` first: it lists every part, where it lives in TV, and how to roll it back. `log.md` is the chronological record of actions on TV.

## Hard rules (operator, 25.11)

- Never write into the original layout **BASE** (`kUwtVNuo`). All 4 TV windows show it. Changes go only into a copy named `BASE · dark`. `tools/restore.mjs` refuses to write elsewhere; `--allow-original` exists for the operator only.
- Never edit, overwrite or publish the original Pine scripts (90 · NQ, 90, RIZ v9.7, RIZ BLUE, DR/IDR). New versions are separate private scripts with the suffix ` · dark`.
- Never touch manual drawings (incl. the 181 «dr» Fibonacci drawings) or other layouts/tabs.
- If a step cannot keep the original recoverable, stop and report.

## Connection

TradingView Desktop with CDP on `127.0.0.1:9222`. Every TV window is a CDP target; `node tools/probe.mjs` lists them with layout name/id, panes and studies. Window 1 = the one with `CME_MINI:MNQZ2026 | BATS:QQQ` (target `309200BC…` on 25.11; ids change after a TV restart, so match by symbols).

## Roll back

| What | Command / action |
|---|---|
| everything settable (canvas, candles, inputs, sessions) | `node tools/restore.mjs all --to baseline` |
| one part | `node tools/restore.mjs 03-dr-idr --to baseline` (or `03`, or `dr-idr`) |
| one pane | add `--pane 0` (left) or `--pane 1` (right) |
| preview only | add `--dry-run` (read-only, allowed on any window) |
| re-apply v2 | `--to v2` |
| Pine parts (04, 05, 06) | remove the ` · dark` instance from the pane; re-add the original or use TV «Indicators ▾ → Templates → Open template… → светлая-исходная MNQ / QQQ» (this replaces all indicators of that pane with the baseline set and inputs) |
| whole window | switch window 1 back to layout BASE (layout menu → BASE). The copy is separate; BASE is never written |
| canvas only, by hand | Settings → Template → «Светлая исходная» → Ok |
| last resort | `baseline/layout-json-<target>.json` is TV's full `saveToJSON()` content per window; `baseline/window-<target>.json` holds every property and input |

`restore.mjs` picks the window whose layout name ends with ` · dark` unless `--target <cdpIdPrefix>` is given. Each run appends a line to `log.md`. It writes chart/series/session properties with `setValue` (no Ctrl+Z step) and inputs with the public `setInputValues`.

## Check state

- `node tools/snapshot.mjs work/now --no-shots --target <prefix>` then `node tools/diff.mjs baseline/window-<prefix>.json work/now/window-<prefix>.json` → `IDENTICAL` means the window equals baseline.
- `node tools/shot-client.mjs <targetId> <file.png>` renders a window even when it is hidden.

## Files

- `baseline/` (git tag `baseline`): `window-*.json` per window (chart, series, sessions, all Script studies with inputs metadata, fib drawings), `layout-json-*.json` (saveToJSON), `layout-state-*.json`, `pine/*.pine` + `pine/index.json` (id, version), screenshots.
- `parts/NN-name/apply.json` (v2) and `revert.json` (baseline), generated by `node tools/build-parts.mjs` from `baseline/window-309200BC.json`. Edit the palette there, regenerate, commit.
- `tools/ui.mjs`: low-level UI driver (real mouse clicks via CDP; `mclick "<text>"` / `mclick "css:<selector>"`). Clicks are risky: check what an element is before clicking, never click «Apply defaults», «Save as default», «Reset settings», layout «Save», or a template name in a list (that applies it).

## Commits

One commit and tag per applied part (`v2-01-canvas`, …), so `git checkout <tag>` shows what was applied at each step.
