# Динамическая карта: проверка отбора и смысла процентов

15.10.2026. Исследование по прямому запросу оператора: проверить отбор до построения нового UI и восстановить смысл
сравнения 14/22/33 %, общего пула 100 % и последовательного «после ближнего — дальше».

## Протокол до нового подсчёта

Это разведочная повторная работа на уже исследованной истории 2006–2025, а не нетронутая внешняя проверка.
Никакой результат сам по себе не принимает новый профиль, C2/C3, алгоритм или интерфейс. Main, SC-1.1, BASE/NOW,
рабочие серверы, 2026 и рыночные файлы не изменяются. Сохраняются только код и агрегаты; строки — в local runtime.

**Предмет.** Для известного закрытого M5-среза t: где наблюдалась цена после него у сопоставимых исторических случаев.
Не переносить результаты Q1/нового экстремума автоматически на этот вопрос. Сравнить два исхода, раздельно:

* `WINDOW_VISIT`: хотя бы одна из трёх будущих M5 диапазоном low–high задела заданную полосу `[lo,hi)`.
  Голосует сессия, один раз на область. YES сохраняется при другом пропуске; NO требует всех трёх M5;
  иначе UNKNOWN. Нельзя заменять объединение трёх диапазонов одним min-low/max-high: между свечами возможен гэп.
* `END_CLOSE`: закрытие последней M5 того же окна лежит в полосе. Одна сессия имеет одно положение на этой M5;
  отсутствующее закрытие — UNKNOWN. Посещение не является закрытием.

**Области известны до исхода.** Три окна одинаковой длины: закрытия t+5/10/15, t+20/25/30 и t+50/55/60 минут.
Только окна, целиком помещающиеся в блок. Полоса — две клетки по 0,1 SD; её центр — текущая клетка цены плюс
смещение −1,0/−0,5/−0,2/+0,2/+0,5/+1,0 SD. Нижняя клетка `floor(10*u_today)+offset−1`, верхняя — на две выше.
Все события одного среза сравниваются на одинаковых размерах области; футурные «лучшие зоны» не выбирают цели.
SD — одна собственная ширина IDR, та же направленная координата `u=d*(p-e)/w`; пути не сдвигаются к today's close.

**Популяция.** NQ/ES/YM × ODR/RDR, подтверждённая исходная фаза. Цели 2016–2025; по одному подтверждённому случаю
на ISO-неделю в каждой связке инструмент/блок: минимальный SHA256(`id|dynamic-field-v1`), без просмотра исходов.
У выбранного случая — все закрытые M5 после собственного подтверждения с полным известным префиксом, пока DR цел.
Аналоги — только строго более ранние торговые даты 2006–2025; их активация уже была, префикс полный, DR ещё цел
на общем ET-часу. Будущий слом не исключает аналог. Поздние/малые weekday-семьи не исключают цель из исследования.
ADR и семья слома вне этой первой проверки, их нельзя считать проверенными. Отдельные срезы одного дня не независимы.

**Отборы, зафиксированные до счёта.** Один и тот же набор метода используется для обоих исходов, всех цен и окон
одного среза; это позволяет сопоставлять стороны без скрытой смены знаменателя.

| Метод | Родитель и правило |
|---|---|
| CLOCK_WD / POS_WD | Семья BASE с днём недели; без цены / `abs(u-u_today)<=1/4` |
| CLOCK_ALL / POS_ALL | Та же сторона и окно подтверждения, все дни недели; без цены / допуск 1/4 |
| CLOCK_GEO / POS_GEO | Тот же инструмент/блок, все стороны/окна в собственной направленной шкале; без цены / допуск 1/4 |
| STATE_ALL | POS_ALL и совпадение сделанных R и X, каждый с допуском 1/4 |
| PATH_ALL | Исходный NOW M3: сделанные R/X с допуском 1/4, последние до шести закрытий; MAE 0,20/max 0,35, минимум три |
| GAPS_ALL | CLOCK_ALL и расстояния close−R и X−close, каждое с допуском 0,10; единый набор для двух сторон |
| POS_K50_ALL | 50 ближайших по позиции среди CLOCK_ALL; при родителе <50 — нет ответа |
| STATE_K50_ALL | 50 ближайших по евклидову расстоянию `(close,R,X)` в SD среди CLOCK_ALL; без обучения весов |

K50 — явный исследовательский вариант с измерением дальности соседей, не скрытое расширение quarter-rule.
Первичные сравнения: POS_ALL−CLOCK_ALL; STATE_K50_ALL−POS_K50_ALL (одинаковая опора);
POS_GEO−POS_ALL. Остальные — диагностика роли weekday, широкой популяции и жёстких фильтров.

**Оценка.** Сохранять n_total, n_known, YES/NO/UNKNOWN. Точка — YES/n_known, границы —
`[YES/n_total,(YES+UNKNOWN)/n_total]`. Для сравнительной точечной оценки в этом исследовании нужны оба n≥20.
Это правило исследования не меняет пороги BASE/NOW/ARRIVE. Неизвестный target остаётся в отчёте, не получает NO.
Нижний Brier лучше; сравнение только на общих отвеченных строках, рядом полное покрытие и причины отсутствия.
Отчёт раздельно по исходу, инструменту/блоку, эпохе, расстоянию, будущему окну; калибровка по диапазонам показанного p.
Средняя ошибка сначала усредняется внутри целевого случая, затем по случаям; CI 95 % пересэмплирует ISO-недели
целиком, 2000 повторов, seed=20261015. Покрытие и ошибки публикуются вместе, лучшая ошибка на малом охвате не победа.
Единственного принятого победителя протокол не назначает; вся история уже видена.

**Проверки смысла до прогона.** Точный SD-допуск/зеркальная рамка; target future не меняет отбор/оценку;
future аналога не меняет отбор, может менять метку; диапазон не равен закрытию; гэп не становится посещением;
один случай не удваивается в области; UNKNOWN не NO; positive-control по известной позиции.

**Проценты и последовательность.** Проверить разбиение 60/40; пересечение посещений с суммой >100 %;
вложенное достижение близкого/дальнего уровня на одном горизонте; невложенные ценово-временные области;
одинаковые маргинальные 14/22 при разных пересечениях и порядке. Оценка «дальше после достигнутого ближнего»
требует собственного датированного вопроса и знания достижения, не получается из ранжирования двух долей.

## Источники и запуск

История 100 %: `meaning/09-chisla-ekrana.md`, `meaning/10-dizajn-24.md`,
`studies/percent_semantics_2026_09_30/`; старый динамический контроль — `studies/lens4_2026_09_30/`.
Расчёт исходного корпуса и префикса переиспользует `lab/now24_validate.py::universe`, `lab/now24.py::series`.
Будущий новый UI и рабочие формулы не меняются.

`python -B studies/dynamic_field_2026_10_15/checks.py --check` — смысловые фальсификаторы.
`--dry` — только формы/скорость на малой части, без вывода сравнительных итогов.
`--run` — полный объявленный недельный срез; `--report` — агрегаты из локальных записей.

Результаты и ограничения будут добавлены после расчёта; этот протокол имеет собственный hash в каждом прогоне.
