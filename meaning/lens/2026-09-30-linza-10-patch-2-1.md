В моей time-first v2 сейчас написано:
«пользователь выбирает закрытую M5 t…»

Это верно для динамического слоя, но недостаточно.
Должно быть сначала:
t₀ имеет специальный статус: это M5 активации/подтверждения DR и источник Baseline Map.

А затем:
каждая t > t₀ создаёт Dynamic Map, используя дополнительный prefix, накопленный после активации.

И ещё одно обязательное правило:
Dynamic Map никогда не переписывает Baseline Map задним числом.

Иначе мы потеряем саму преемственность:
авторский исходный слой → наше динамическое расширение.

---

PATCH 2.1 к `DR_Lab_semantic_spec_time_first_v2.md`
Специальный статус M5 активации: Baseline Map → Dynamic Maps
Статус: срочная смысловая поправка к спецификации v2.
Приоритет: этот патч имеет приоритет над формулировками v2, где любая выбранная закрытая M5 могла читаться как равноправный исходный `t`.
Назначение: остановить дрейф реализации. Не переписывать весь объект кластеров; исправить иерархию временных срезов.
1. Главная поправка
В time-first конструкции не все закрытые M5 равноправны.
Есть два разных слоя:

1. Baseline / Activation Map — возникает один раз в момент фактической активации / подтверждения DR.
2. Dynamic State Maps — возникают на каждой следующей закрытой M5 после активации и используют уже накопившийся дополнительный prefix сегодняшней сессии.

То есть базовая временная ось не начинается с произвольно выбранной свечи.
Она начинается с:
первой закрытой M5, которая фактически выполнила правило активации / подтверждения данного DR-сценария.
Обозначим её:
`t0`.
`t0` определяется событием, а не фиксированным временем суток.
2. Активация может произойти в любое допустимое M5-время
Не кодировать и не подразумевать:

* 10:35 как обязательное `t0`;
* 10:45 как обязательное `t0`;
* любой другой фиксированный clock-time.

Пример:

* 10:35 — DR ещё не активирован;
* 10:40 — ещё нет;
* 10:45 — ещё нет;
* свеча 10:45–10:50 закрывается так, что правило подтверждения выполнено;
* `t0 = 10:50`.

Тогда:

* `10:50` → Baseline / Activation Map;
* `10:55` → Dynamic Map 1;
* `11:00` → Dynamic Map 2;
* `11:05` → Dynamic Map 3;
* и т. д.

Если подтверждение возникло в 11:20, `t0 = 11:20`.
3. Что такое Baseline / Activation Map
На `t0` система впервые имеет подтверждённый DR-сценарий.
В этот момент задаётся исходный исторический вопрос:
«После такого подтверждения DR, возникшего в такое время и с такими известными к `t0` условиями, куда исторически доходила цена похожих сессий в каждую следующую M5?»
Это нулевой исторический снимок сценария.
Он должен:

* строиться на prefix, доступном ровно к `t0`;
* использовать исторические аналоги, сопоставимые по состоянию на их собственном `t0`;
* сохранять фактическое время подтверждения как часть ключа / состояния, если matcher его использует;
* строить то же time-first `price × future-M5` range field, определённое в v2.

Важное происхождение
Baseline сохраняет преемственность с авторским подходом:
после факта подтверждения рассматривается историческая группа соответствующих подтверждённых сцен и их дальнейшее поведение.
Но наша конкретная визуализация `M5 high-low × future time` — это расширение DR Lab, если она не воспроизводит буквальный опубликованный объект автора.
Не приписывать автору наши собственные динамические механизмы.
4. Что такое Dynamic State Map
После `t0` сегодняшняя сессия начинает раскрывать дополнительный путь.
На каждом следующем закрытии M5:
`t1 = t0 + 5m`
`t2 = t0 + 10m`
`t3 = t0 + 15m`
...
строится новый вопрос:
«Теперь, когда к исходному подтверждению добавилось ещё столько-то реально наблюдённого пути, что происходило дальше у исторических сцен, сопоставимых уже с этим расширенным состоянием?»
Dynamic Map использует:

* тот же основной `price × future-M5` объект;
* новый prefix до текущего `tn`;
* новый `C_tn`, если matcher зависит от новых доступных признаков;
* только будущее после `tn`.

5. Baseline и Dynamic нельзя смешивать
Baseline Map не является просто `Dynamic Map at first index`.
У неё отдельная смысловая роль:
что история показывала в момент рождения подтверждённого DR-сценария.
Dynamic Map отвечает:
как эта историческая картина изменилась после появления новой информации сегодняшнего пути.
Поэтому:

* Dynamic Map не переписывает Baseline Map задним числом;
* Baseline должен быть доступен как исходный снимок;
* динамические карты могут отличаться от Baseline без объявления, что Baseline был «ошибкой»;
* изменение распределения означает изменение условия / prefix, а не исправление прошлого расчёта.

6. Правильная временная иерархия
Не:
`произвольная M5 t → карта`
А:

```
DR/IDR сформирован
    ↓
ожидание подтверждения
    ↓
первая M5, закрывшая условие подтверждения = t0
    ↓
BASELINE / ACTIVATION MAP
    ↓
следующая закрытая M5 = t1
    ↓
DYNAMIC MAP(t1)
    ↓
следующая закрытая M5 = t2
    ↓
DYNAMIC MAP(t2)
    ↓
...
```

Это обязательная архитектурная иерархия.
7. Hover / выбор прошлой сегодняшней M5
После активации пользователь может выбрать любую уже закрытую M5 `tn ≥ t0`.
Тогда UI должен показывать:
какое историческое поле было бы доступно именно на этом срезе сегодняшнего дня.
Это позволяет пройти эволюцию дня:
`activation → +5m → +10m → +15m → ...`
и увидеть:
как менялась историческая проекция по мере поступления новой информации.
Если пользователь выбирает `t0`, он видит Baseline.
Если выбирает `t1`, `t2`, ... — соответствующий Dynamic Map.
До `t0` подтверждённого directional DR-field в этом смысле ещё нет; если существует pre-confirmation режим, он должен иметь отдельную семантику и не притворяться Baseline.
8. Что остаётся неизменным из time-first v2
Этот патч не отменяет:

* time-first ориентацию;
* M5 как минимальный смысловой масштаб;
* high-low range как базовый future-price вклад M5;
* `price-bin × future-M5` cell shares;
* separation raw field / cluster / overlay;
* first-reach как производную статистику;
* path-conditioned sequence как отдельный модуль;
* запрет использовать +1.0 как определение основного поля;
* unique-session accounting для mass контура;
* unknown / gap semantics.

Меняется только одно фундаментальное положение:
временная система имеет специальную нулевую точку `t0` — событие активации DR.
9. Что инженеру нельзя сейчас сделать
До учёта этого патча нельзя:

* реализовать любую закрытую M5 как равноправную «точку рождения» поля;
* потерять или перезаписывать Baseline после появления следующей M5;
* фиксировать Baseline на конкретном clock-time;
* смешивать confirmation-time и elapsed-time after confirmation;
* называть динамическое пересопоставление «авторским слоем»;
* использовать будущую информацию после `t0` при построении Baseline.

10. Минимальные тесты
A. Активация в 10:50
Подтверждения нет до закрытия 10:50.
Ожидание:

* до 10:50 Baseline отсутствует;
* `t0 = 10:50`;
* первая Baseline Map строится от 10:50;
* 10:55 — уже Dynamic Map.

B. Активация в 11:20
Ожидание:

* `t0 = 11:20`;
* никакой скрытой привязки к 10:30/10:35/10:50 нет.

C. Baseline не переписывается
Пусть в 10:50 Baseline показывал одну картину, а в 11:05 Dynamic Map — другую.
Ожидание:

* обе картины доступны как разные исторические срезы;
* Baseline 10:50 сохраняет исходный `C_t0` и исходное поле;
* Dynamic 11:05 использует только prefix до 11:05 и своё будущее.

D. Hover назад
Сегодня уже 12:00.
Оператор выбирает свечу 10:50.
Ожидание:

* видит Baseline, рассчитанный по информации, доступной к 10:50;
* сегодняшние события 10:55–12:00 не используются для изменения состава Baseline-группы.

Оператор выбирает 11:20.
Ожидание:

* видит Dynamic Map для prefix до 11:20.

11. Каноническая формула после патча
Layer 1 — Baseline / Activation
`DR formed`
→ `actual confirmation event`
→ `first confirming closed M5 = t0`
→ `prefix-honest historical cohort at t0`
→ `time-first future M5 range field`
→ `Baseline Map`.
Layer 2 — Dynamic DR Lab extension
`Baseline exists`
→ `new closed M5 tn > t0`
→ `expanded observed prefix`
→ `re-match / re-condition using only information available by tn`
→ `future M5 range field after tn`
→ `Dynamic Map(tn)`.
12. Одна фраза для инженера
Не строй один универсальный “map(t)” без иерархии. Сначала существует специальный Baseline на фактической M5 активации DR; только после него каждая следующая закрытая M5 создаёт динамический пересчёт из расширенного сегодняшнего состояния.
13. Одна фраза для трейдера
В момент подтверждения DR я вижу исходную историческую карту похожих подтверждений; после каждой следующей закрытой пятиминутки DR Lab показывает, как эта историческая картина меняется с учётом уже прожитого сегодняшнего пути.
