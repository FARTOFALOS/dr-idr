## Что из них сделано

Цель 13.10 требовала не новой спецификации, а исполняемого механизма. Он сделан в ветке `semantic-trace` и описан в
[`trace/README.md`](../../../trace/README.md):
- **машинная модель** — модуль LinkML поверх неизменённой схемы SC-1.1;
- **каталог** — 130 идентификаторов 0.1 привязаны к существующим объектам, коду и проверкам; непокрытое — границами;
- **исполнение** — `lab/semtrace.py`;
- **свидетельства прогона** — `studies/trace_2026_10_13/`.

Поправки 0.2 вошли так:
- §1, границы реализации: записи `T14`, `T16`, `A20`, `PROC-15`, `PROC-17` (поле `correction_0_2_ru`) и границы
  `GAP-05`, `GAP-06`, `GAP-08`;
- §2, определения и экземпляры: классы SC-1.1 переиспользованы; добавлены только `Q1TargetIdentity`,
  `Q1IssueIdentity`, `Q1OutcomeLink`, `ArchitectureCheckEvidence` и привязки;
- §3, раздельные ветви отбора и меток, независимые оценки: проверки `FUTURE-TARGET`, `FUTURE-MEMBERS`, `BUNDLE-COUNTS`;
  поля `ClaimAssessment`;
- §4, раздельные типы привязок: `Statistical`, `Fact`, `AbsencePresentationBinding` — проверены в замкнутом мире;
- §5, проверки связей сверх структуры: статические и сценовые проверки `lab/semtrace.py`.

## Что из 0.1 не принято машиной как истина

0.1 не нормативен. Каталог берёт из него идентификаторы и смысл записей, но статус каждой записи **не переписывает** —
его считает прогон. Решение по профилю берётся из источников (`STANDING`), а не из текста 0.1.

Где 0.1 расходится с репозиторием, побеждает репозиторий, а расхождение записано (`correction_0_2_ru`, граница
`BND-02`). Пример: в 0.1 T14 и T16 «OPEN, реализации нет», а в PR #7 есть кандидат.
